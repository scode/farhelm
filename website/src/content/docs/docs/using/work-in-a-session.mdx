A session's terminal is the agent's own terminal: you type to the agent exactly as you would if you had started it in a
terminal yourself, and everything it prints shows up here. Farhelm does not sit between you and the agent's prompts.

## The header

  name="work-in-a-session/header"

/>

The buttons at the header's right end restart, replace, clone, and delete the session; [Stop, restart, and
resume](/docs/using/stop-restart-resume/) covers them.

## Open a shell beside the agent

<Screenshot
  name="work-in-a-session/tabs"
  alt="The tab strip with the agent tab and the + terminal button explained."
/>

Each shell tab is named **Terminal 1**, **Terminal 2**, and so on, and runs on the same host as the agent, in the
session's directory. It belongs to the session: it keeps running when you switch to another session, and deleting the
session closes it. Closing a tab yourself asks you to confirm first, since it ends whatever is running in it.

**A−** and **A+** at the right end of the tab strip change the terminal's text size, as do Cmd+Shift+minus and
Cmd+Shift+plus.

## Copy, paste, and links

Selecting text copies it. Some agents take over the mouse for their own interface, and then a plain drag does not select
anything; hold Option while you drag to select anyway.

To give the agent a screenshot or a file, paste it or drop it onto the terminal. Farhelm uploads it to the session's
host and types its path at the prompt, so it works the same on a remote host as on your Mac.

Links in the terminal open in your browser. Hovering over one shows where it really goes, and Farhelm warns you when
that differs from the text it is attached to.

The terminal keeps at least the last 10,000 lines for scrolling back. How much of that history survives a restart is in
[What survives what](/docs/how-it-works/what-survives-what/).

## When the connection drops

If Farhelm loses its connection to the session, a banner over the terminal says it is reconnecting, and **reconnect
now** tries again straight away. The agent keeps running on its host the whole time; you only lose the view of it until
the connection is back.

A session's terminal can be open in more than one window at a time, say the desktop app and a browser tab, but only one
of them types to it. When another window takes over, this one says so and offers to take control back.

A session outlives its agent. Stopping the agent, or a reboot ending it, leaves the session in the list with its
terminal readable, ready to start again. Only deleting a session removes it.

## The header's actions

<Screenshot
  name="stop-restart-resume/header-actions"
  alt="The buttons at the right of the session header, with restart, replace, and clone explained."
/>

Restart always continues the session's own conversation; there is no restart that starts a new one. When Farhelm has
no conversation it can resume, because the agent cannot report one or none was captured, **restart** is greyed out and
hovering over it says why. Replace is then how you start the session over. [Supported agents](/docs/agents/) says which
agents Farhelm can resume, and a command you run yourself needs an agent and a resume command declared for it; see
[Custom commands](/docs/agents/custom-commands/).

**restart with** resumes the conversation the same way, with different settings: another model, effort, permission
mode, or workspace trust. It is greyed out whenever **restart** is.

**replace** starts the agent again from a fresh conversation, with the same agent, settings, and directory, and asks you
to confirm first, since the old conversation is not kept. **replace with** opens the
[session launcher](/docs/using/start-a-session/) filled in with this session's choices; change what you like, and the
new session takes this one's place. **clone** opens the launcher the same way but leaves this session alone, so you end
up with two.

If the agent is still working when you choose **restart**, Farhelm asks you to confirm first, since restarting stops
it. A session whose agent has already ended restarts straight away. **restart** never asks the YOLO question, even for a
YOLO session, since it relaunches a choice you already made; **restart with** asks it when the new settings are YOLO.

## Stop or delete

<Screenshot
  name="stop-restart-resume/row-menu"
  alt="A session's menu with stop and delete explained."
/>

Both are in a session's menu in the [session list](/docs/using/session-list/), and delete is also the red button at the
right of the session header. Delete asks you to confirm, with one exception: from the session list, a session that has
already ended and has no shell tabs open is deleted at once.

## After a reboot

When a host reboots, every session on it ends, and each shows as interrupted. Farhelm does not start them again by
itself; the session's terminal says it is waiting for you to choose restart or replace. Restart resumes the
conversation if Farhelm can, and replace starts the session over.
[What survives what](/docs/how-it-works/what-survives-what/) has what else a reboot, or restarting Farhelm itself, does
and does not keep.

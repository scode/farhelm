In the Farhelm app on your Mac, Cmd+N opens the launcher too, even while you are typing in a terminal.

When you launch, the launcher closes, the new session appears in the [session list](/docs/using/session-list/), and its
terminal opens, ready for your first prompt.

## The launcher at a glance

<Screenshot
  name="start-a-session/launch-button"
  alt="The launch button reading launch Codex, local (this machine), and the directory, with the summary under it."
/>

**cancel**, Escape, or a click outside the launcher closes it and forgets your choices. **reset choices** clears the
agent, model, and effort, and puts permissions and trust back to the ones the launcher remembers (see the note below);
it keeps the host, directory, and name.

## Choose where it runs

<Screenshot
  name="start-a-session/destination"
  alt="The launcher's destination part: the folder or managed checkout choice, the host menu, the directory field, and directory history dropdown."
/>

With no session open, the host menu starts on the machine you are using, listed as **local (this machine)**. A host that
is not connected right now shows its state next to its name, such as "unreachable, retrying", and you cannot launch on
it until it is back. [Add a remote host](/docs/get-started/add-a-remote-host/) covers adding hosts.

**browse folders on** the host lists its directories one level at a time, for when you would rather find a directory
than type it. **name (optional)** names the session in the session list; leave it empty and Farhelm picks a name.

## Choose the agent and how it runs

<Screenshot

<Screenshot

Not every agent has every choice, and some offer more permission modes than these two. Switching to another agent
clears any choice it cannot take, and the launcher tells you when it does. [Supported agents](/docs/agents/) lists what
each agent offers; workspace trust is explained on the [Codex](/docs/agents/codex/), [Muse](/docs/agents/muse/), and
[Pi](/docs/agents/pi/) pages. To run something that is not one of these agents, switch the launcher to its **command**
tab, covered in [Custom commands](/docs/agents/custom-commands/).

NOTE: The launcher remembers the permissions and trust of your last launch from its **agent** tab, in any Farhelm
window. After one YOLO launch, the next launcher opens on **yolo** too. Launches your agents start, custom commands, and
plain **replace** do not change what it remembers.

## Confirm a YOLO launch

Before a YOLO launch, Farhelm asks you to confirm. Every host asks until you tell it not to.

<Screenshot
  name="start-a-session/yolo-confirmation"
  alt="The YOLO confirmation, with its two start buttons explained."
/>

It is not only the **yolo** choice that asks. Farhelm offers Pi and OpenCode only in YOLO mode, so every launch of
either asks, and so does a custom command you say runs without approval prompts. Farhelm goes by that answer alone and
never reads the command to check it. It does not take an agent's word for it, though, and an agent cannot confirm a YOLO
launch: on a host that asks, an agent cannot start a YOLO session or a custom command at all ([Approve what agents
do](/docs/using/approve-agent-requests/#yolo-sessions-and-custom-commands)).

To change your mind about a host later, use its settings. [Manage hosts](/docs/using/manage-hosts/) covers the rest of
them.

## Launch a setup you used before

<Screenshot
  name="start-a-session/recent-setups"
  alt="The recent setups list under the launcher's search box, showing three setups for the chosen directory."
/>

A setup is the agent, model, effort, permissions, trust, and directory of a launch you made on the launcher's **agent**
tab, however you filled it in.
Farhelm keeps them separately for each host, and shows up to three; type `recent:` in the search box to find older ones.

To start another session like one you already have, choose **clone** from that session's menu instead. It opens the
launcher with that session's choices already filled in. [Stop, restart, and resume](/docs/using/stop-restart-resume/)
covers it, along with **replace with…**.

## Search instead of clicking

<Screenshot
  name="start-a-session/search"
  alt="The launcher's search box with claude typed, listing matching agents, models, and setups."
/>

The search box has the keyboard focus when the launcher opens, so you can set up a whole launch without the mouse.
Typing a path offers to use it as the directory or to browse it. Away from the search box, Enter on one of the
launcher's choices, such as a harness, an effort, or a recent setup, picks it and launches with everything as it then
stands.

In the directory dropdown, Enter chooses a suggestion only after an arrow key has highlighted it, without launching.
With nothing highlighted, Enter in the directory field launches the path you typed.

<Screenshot
  name="start-a-session/search-name"
  alt="The search box with name: fix login bug typed, offering to set that as the session's name."
/>

A few other prefixes do something no plain search does: `gh:` starts a [managed
checkout](#start-from-a-managed-checkout), `tl:` applies one of your [launch
templates](/docs/using/launch-templates/), saved sets of launcher choices, `trust:` is the only way to set workspace
trust from the search box, and `perms:` the only way to pick **default** permissions there. The rest only narrow a
search to one kind of thing: `host:`, `harness:`, `model:`, `effort:`, `folder:`, and `recent:`. `host:local` picks the
machine you are using.

## Start from a managed checkout

A session can also start in a new clone of a GitHub repository instead of an existing directory. Farhelm calls this a
managed checkout: it makes the directory for the session and moves it into the trash when its last session is deleted
(see [Stop or delete](/docs/using/stop-restart-resume/#stop-or-delete)). The
[trash](/docs/using/session-list/#managed-checkout-trash) beside **new** shows where those directories are and lets you
clean them up. Choose **managed checkout** under destination, enter the repository as `owner/repo`, and select its
suggestion. You can also type `gh:owner/repo` in the search box and choose **Managed checkout: owner/repo**. Farhelm
suggests repositories you have launched or cloned before, but it does not search GitHub, so type a new one in full.

Before you launch, the launcher shows the directory the clone will go into, and the launch button waits until it does.
Each checkout gets a new directory of its own, named after the repository and numbered (`farhelm-1`, `farhelm-2`, and so
on), or named after the repository and the session if you gave the session a name (`farhelm-fix`). **folder** switches
back to an ordinary directory.

**Clone** on a session in a managed checkout starts a managed checkout of the same repository, even if the session runs
in a subdirectory. The name starts as the source's name plus `-clone`, then `-clone-2`, `-clone-3`, and so on when
taken. Editing the name keeps exactly the name you enter and reports a conflict if its directory is taken. **folder**
restores the source's directory and name. **Replace with** and **Replace** keep the existing directory.

When you launch, Git brings the host's cache of the repository up to date, then clones the default branch in the
session's terminal. The agent starts once that finishes. Both commands use the host's own Git credentials, so anything
Git asks for, such as a password, shows up in the terminal for you to answer. A private repository without a credential
helper can ask twice. If either command fails, the session's status shows error, the terminal says what went wrong,
and any partial clone stays where it is.

The cache makes repeated managed checkouts faster and takes roughly the disk space of one extra copy of each repository
on each host. It lives under Farhelm's state directory on that host, in `repo-cache/<owner>/<name>.git`, outside your
checkout directory. Farhelm removes caches unused for more than 30 days when the host's supervisor, the program that
keeps its sessions running, starts (see [The pieces](/docs/how-it-works/the-pieces/)). You can delete a cache directory
by hand at any time; existing checkouts stay independent, and the next managed checkout downloads it again. Avoid doing
that while a checkout is being prepared, since it can make that launch fail, and leave the sibling `.lock` files in
place so concurrent checkouts still take turns. A cache failure names its path in the terminal and stops the clone.

Managed checkouts need one setup step first: telling Farhelm which directory new checkouts go into. Until you have,
choosing **managed checkout** asks for it.

<Screenshot
  name="start-a-session/checkout-setup"
  alt="The launcher in managed checkout mode asking for the checkout folder, with the field and its save button explained."
/>

To change the directory later, or save an empty field to clear it, use the same field in **settings**, opened from the
gear beside the version number at the top of the sidebar.

Settings also has a **post-clone command** field for a shell command to run in each new clone, on its host, before the
agent starts (installing dependencies, say). Save it explicitly; empty the field and save to remove it. Changes affect
future checkouts only.

The directory and the command apply to every host. To give one host a directory or command of its own, run
`farhelm helm checkout-config` on the machine that runs the helm (the program that serves the Farhelm app; see
[The pieces](/docs/how-it-works/the-pieces/)); `farhelm helm checkout-config --help` lists the options. A host given its
own directory or command there keeps it whatever **settings** says.

## When a launch fails

What you see depends on how far the launch got. When Farhelm can tell before starting anything that the launch will not
work, for example because the directory does not exist on that host or the host just went offline, it shows the reason
beside the launch button and keeps your choices, so you can fix it and launch again. No session is created. When
the agent itself fails to start, for example because it is not installed on that host, the session is created and its
status shows error; the agent's page in [Supported agents](/docs/agents/) says what to install. An agent that starts and
then quits shows exited. [Read the session list](/docs/using/session-list/) explains each status.

On a Mac, Cmd+N opens the session launcher too, even while you are typing in a terminal; the Linux app has no shortcut
for it. See [Keyboard shortcuts](/docs/using/keyboard-shortcuts/) for the app's other keys.

When you launch, the launcher closes and the new session appears in the [session list](/docs/using/session-list/).
Its terminal opens, where you can type your first prompt, or supply it in the launcher. If you have clicked or typed
elsewhere in the meantime, Farhelm leaves you where you are and briefly shows **Started “name”** at the bottom of the
window instead.

If the host takes more than about two seconds to answer, a small status at the bottom of the window shows the host's
name and how many seconds you have been waiting. You can keep working in other sessions meanwhile. If the launch fails
or needs an answer from you, the launcher comes back with your choices. If you have moved on by then, a banner across
the top of the window says so instead, and its **Open launcher** brings the launcher back.

## The launcher at a glance

Type in the command field at the top to fill in your launch. Recent setups and templates sit beside the form, where
you can choose the destination and edit the **Agent** or **Command** settings before pressing **Launch**.

<Screenshot
  name="start-a-session/launch-button"
  alt="The launcher's footer with Cancel, Reset choices, Save as template, and Launch."
/>

**Cancel**, Escape, or the × (Close) at the top of the launcher closes it and forgets your choices. **Reset choices**
clears the agent, model, and effort, and puts permissions and the wrapper prefix back to what the launcher remembers; it
keeps the host, directory, and name.

## Choose where it runs

<Screenshot
  name="start-a-session/destination"
  alt="The launcher's destination part: the folder or managed checkout choice, the host menu, the directory field, and directory history dropdown."
/>

The **Host** menu lists your existing hosts and lets you start in a new environment. It offers **New container** when
you have a host that can run containers, and **New sandbox** once a Tensorlake API key is saved.
[Container sessions](/docs/agents/containerized-sessions/) use a recipe and a Linux container host;
[sandbox sessions](/docs/using/tensorlake-sandboxes/#give-each-session-its-own-sandbox) use a recipe and your Tensorlake
account, and Farhelm asks before creating the billed sandbox. Either can clone a [managed
checkout](#start-from-a-managed-checkout) inside or start in the new environment's home. Opening **+** (New session) while a sandbox or container session is open preselects a new one from
that session's recipe, on the same Tensorlake account or container host. The host and directory controls below apply to an
existing host.

With no session open, the **Host** menu starts on the machine you are using, listed as **Local (this machine)**. A host
that is not connected right now shows its state next to its name, such as "Unreachable, retrying", and you cannot launch
on it until it is back. A suspended sandbox or a stopped container is the exception: launching there wakes it first
([When a launch fails](#when-a-launch-fails)). [Add a remote host](/docs/get-started/add-a-remote-host/) covers adding hosts.

The directory field starts at the directory of your last agent launch on that host, or at the host's home directory if
you have not launched an agent there yet; a launch into a new managed checkout, a new container or a new sandbox does not count. With
a session open on the same host, it starts at that session's directory instead. Changing the host switches to that
host's directory, unless you typed or picked one yourself. With **Folder** chosen, the launcher also checks the
directory on a connected host: if it does not exist there, or is not a directory, a warning under the field names the
host. You can still launch; the host checks the directory again when you do.

The directory shares one address field with the **Host** menu at its start. The folder button at the end of that field
(**Browse**) lists the directories under the current path one level at a time. Choosing one of
the directory list's entries fills the field without
launching. **Local home** also switches the host to **Local (this machine)**. With the list open, Escape closes the list
first. **Name** (optional) names the session in the session list; leave it empty and Farhelm picks a name.

## Choose the agent and how it runs

<Screenshot
  name="start-a-session/harness-and-model"
  alt="The agent choices with Codex selected and the Model field below them."
/>

To get a family's latest model without looking up its full name, type the family's short name in **Model** (such as
`sol`, `fable` or `glm`) and press Enter. If you have not chosen an agent yet and only one
offers that family, Farhelm chooses it for you; otherwise it asks you to choose one first. Earlier versions of each
family are listed under **Older models**. Typing the same short name in the launcher's command field highlights that latest
model too.

<Screenshot
  name="start-a-session/effort-and-permissions"
  alt="The effort and permissions choices, each explained."
/>

Not every agent has every choice, and some offer other permission modes; [Permission modes](/docs/agents/#permission-modes)
explains each, including **Custom** for supplying your own permission flags. Switching to another agent
clears any choice it cannot take, and the launcher tells you when it does. You can choose **Guarded** or **YOLO** before
choosing an agent. If choosing an agent replaces a permission you chose with a riskier mode, a red banner says so and
offers **Undo**, including on your first agent choice. [Supported agents](/docs/agents/) lists what
each agent offers. To answer directory-trust questions automatically, use the
[agent trust settings](/docs/using/start-a-session/#workspace-trust). To run something that is not one
of these agents, start [Bash or Zsh, after the agent chips,](/docs/agents/shells/) or use the **Command**
tab for a [custom command](/docs/agents/custom-commands/).

To start a known agent through another command, open **More options** on the **Agent** tab and enter a **Wrapper prefix**. Farhelm places it
before the command it builds for that agent; [Agent wrappers](/docs/agents/agent-wrappers/) explains what the wrapper
must pass through and when to use a custom command instead.

NOTE: The launcher remembers permissions from your last agent launch, and the last wrapper prefix separately for each
agent or shell. After you launch with **YOLO** chosen for an agent whose default is not YOLO, the next launcher
opens on **YOLO** too;
**Custom** flags are never remembered this way. Launches
your agents start, custom commands, and plain **Replace** do not change what it remembers.

## Continue a conversation you know

If you know an agent conversation's id, open **More options** on the **Agent** tab and enter it in **Conversation ID**
(**Session ID** for Goose and OpenCode, **Chat ID** for Cursor) to continue that conversation instead of starting fresh.
This works in New, Clone and Replace with, for an agent in an existing directory. Pi and OMP ask for a **Session file**
instead; use its absolute path or a path relative to the session directory, without spaces or `~`.

The choice applies to this start only. Templates and recent setups do not save it, and a later Clone starts fresh.
The agent handles a mistyped id. If Farhelm started the Goose conversation, **Restart** becomes available when Goose
reports it again. To reopen a Cursor or OpenCode conversation later, enter its id again. For restarting a session whose
id Farhelm never learned, see [Restart with](/docs/using/stop-restart-resume/#the-headers-actions).

## Supply the first message

For agents that accept one, **Initial prompt** supplies the first message when the session starts. The box accepts
multiple lines, and Enter adds a line without launching. Restart, Clone and Replace do not send the message again;
Clone and Replace with open with it cleared. Picking a recent setup leaves a message you have already typed alone.
Goose, Pi, Bash, Zsh and custom commands have no initial-prompt box, and Muse cannot combine one with a conversation id.

To reuse a message for new sessions, save it in a [launch template](/docs/using/launch-templates/).

## Confirm a YOLO launch

Before a YOLO launch, Farhelm asks you to confirm unless that host has **Start YOLO sessions without asking** on.
New [Tensorlake hosts](/docs/using/tensorlake-sandboxes/#add-a-sandbox-host) start with this on; other hosts ask until
you tell them not to. This setting skips the confirmation, not the launcher's permission choice.

<Screenshot
  name="start-a-session/yolo-confirmation"
  alt="The YOLO confirmation, with answers to start guarded instead, start YOLO once, stop asking on this host, or cancel."
/>

In the session launcher, **Cancel** returns to your draft with nothing started. In **Replace**, it leaves you at
the original session.

If you chose **YOLO** and the agent also offers **Guarded**, **Start guarded session instead** starts it with the agent's
own safety checks. This choice is available in the session launcher and **Restart with**. When a plain **Replace**
asks for YOLO confirmation, **Replace as guarded instead** is available for saved agent sessions that Farhelm treats
as YOLO when the agent offers Guarded. It starts a new session with Guarded and your current workspace trust settings.
Sessions with **Custom** permission flags keep the YOLO answers.

On a host that asks, it is not only the **YOLO** choice that asks. **Custom** permission flags ask too, because Farhelm does not check what
they do. Farhelm offers Pi and OpenCode only in YOLO mode, so every launch of
either asks. Goose runs in YOLO mode unless you pick one of its approval modes, so its launches ask too, and
so does a custom command you say runs in YOLO mode. Farhelm goes by that answer alone and never reads the command to
check it. Cursor defaults to YOLO. A plain **Replace** of an older agent session with no recorded permission also
asks for confirmation. On a host that asks, an agent cannot start a YOLO session or a custom command at all ([Approve what agents
do](/docs/using/approve-agent-requests/#yolo-sessions-and-custom-commands)).

To change your mind about a host later, open **Hosts** at the foot of the navigation rail and choose **Settings** from
that host's `⋯` menu. [Manage hosts](/docs/using/manage-hosts/) covers the rest of a host's settings.

## Launch a setup you used before

<Screenshot
  name="start-a-session/recent-setups"
  alt="The Recent list beside the form, showing previous setups that match the chosen directory."
/>

A setup keeps the agent, model, effort, permissions, wrapper prefix and destination of a launch you made on the
launcher's **Agent** tab, however you filled it in. Farhelm keeps setups separately for each host, and keeps launches
into a new sandbox or container on their own, so they stay after that sandbox or container is deleted. The launcher
shows up to three, from the chosen host and from your new sandboxes and containers. Click a setup to fill in the form.
With the command field empty, you can press ↓ to move into the list, then Enter on a recent setup to launch it. Type
`recent:` to find older setups or to reach them when the window is too narrow to show the list.

A setup that made a new sandbox or container names the recipe and where it runs, such as "web container on build1".
Matching setups can show even when the selected host is disconnected or you already have a recipe selected. Choosing
one restores the recipe and where it runs. The next launch creates a fresh sandbox or container. If the recipe or
container host has been removed, choose another before launching.

In **Replace with…**, these setups are disabled because the replacement stays in the existing environment. Enter on a
highlighted setup there replaces the session you opened it from, so its key reads **⏎ Replace**.

To start another session like one you already have, choose **Clone** from that session's menu instead. It opens the
launcher with that session's choices already filled in. [Stop, restart, and resume](/docs/using/stop-restart-resume/)
covers it, along with **Replace with…**.

## Search instead of clicking

The command field has focus when you start a new session, clone, or choose Replace with. You can type an agent, host,
model, directory or session name as soon as the launcher opens. Results take the place of the recent setups and
templates, or open under the field in a narrow window.

<Screenshot
  name="start-a-session/search"
  alt="The launcher with claude typed in the command field and matching agents, models, and setups beside the form."
/>

Enter takes the highlighted result. Typing a path offers to use it as the directory or to browse it. When nothing
matches ordinary text, the list offers **Set session name**. For example, type `asdf` and press Enter to name the
session. With the field now empty, a second Enter launches the setup in the form. A prefix with no matches shows why.
Escape hides the results and keeps your text. Press Enter to show them again. You can also edit the form directly
while results are open. A click in the form closes them.

In the directory dropdown, Enter chooses a suggestion only after an arrow key has highlighted it, without launching.
With nothing highlighted, Enter in the directory field launches the path you typed.

<Screenshot
  name="start-a-session/search-name"
  alt="The command field with name: claude typed, offering Claude as the session name."
/>

A few other prefixes do something no plain search does: `gh:`
starts a [managed checkout](#start-from-a-managed-checkout), `tl:` applies one of your [launch
templates](/docs/using/launch-templates/), saved sets of launcher choices,
and `perms:` picks a [permission mode](/docs/agents/#permission-modes). You can also type
`guarded` or `yolo` without a prefix, even before choosing an agent; `perms:guarded` and `perms:yolo` work then too.
Other permission modes and effort choices need an agent first. Rejections and errors appear in yellow, while ordinary
typing hints keep the normal text color. `effort:default` returns to your agent's default
reasoning effort. The rest only narrow a
search to one kind of thing: `host:`, `harness:`, `model:`, `effort:`, `folder:`, and `recent:`. `host:local` picks the
machine you are using.

For a setup you use often, mark a [quick-launch template](/docs/using/launch-templates/#quick-launch). Cmd+P on a Mac,
or Ctrl+Shift+P on Linux, starts it directly. A YOLO question or failed launch opens the session launcher with the setup
ready to finish.

For a saved setup you know by name, Cmd+J on a Mac or Ctrl+Shift+J on Linux opens a
[template-only list](/docs/using/launch-templates/#quick-launch). Type its name and press Enter to start it; if it
needs more choices, the session launcher opens with its saved choices applied.

For several favorite setups, give templates [number shortcuts](/docs/using/launch-templates/#number-shortcuts): Cmd+0–9
on a Mac, or Ctrl+Shift+0–9 on Linux.

You can also [combine templates from the keyboard](/docs/using/launch-templates/#combine-templates-from-the-keyboard):
Cmd+X on a Mac, or Ctrl+Shift+X on Linux, then their number keys and Enter. Later templates override earlier
choices, so a project setup can be combined with a different agent.

While New, Clone, Replace with or Restart with is open, the **⚡**, number and sequence shortcuts apply templates to the
current draft instead of starting a session; the template list's shortcut does nothing there. You can stack several
presses, then review the choices before pressing **Launch**. The sequence prefix works in the launcher's text fields
when no text is selected; with text selected, the keys keep their usual meaning, such as Cut on a Mac.

## Start from a managed checkout

A session can also start in a new clone of a GitHub repository instead of an existing directory. Farhelm calls this a
managed checkout. It makes the directory for the session. On an ordinary host, deleting its last session moves it into
the trash (see [Stop or delete](/docs/using/stop-restart-resume/#stop-or-delete)). The
[trash](/docs/using/session-list/#managed-checkout-trash) at the top of the session list shows where those directories are and lets you
clean them up. In a [container session](/docs/agents/containerized-sessions/) or
[sandbox session](/docs/using/tensorlake-sandboxes/#give-each-session-its-own-sandbox), the clone lives inside and
Delete removes it permanently, without trash, unless another session still uses it; deleting the last session there
removes the whole environment too.

Choose **Managed checkout** in **Destination**, enter the repository as `owner/repo`, and select its suggestion. You
can also type `gh:owner/repo` in the command field and choose **Managed checkout: owner/repo**. Farhelm suggests
repositories from previous Managed checkout launches across your helm. The same history appears on every host and
when you start a new sandbox or container. Type a new repository in full.

On an existing connected host, the launcher shows the directory the clone will go into before launch, and the launch
button waits until it does. A new container or sandbox picks its directory inside once it is ready. On a suspended
sandbox or a stopped container, the launcher says the directory is picked once the host is ready, and one **Launch**
wakes the host, picks the directory and starts the session.
[Quick launch](/docs/using/launch-templates/#quick-launch) creates that directory directly: marking the template means
you have chosen to start it without seeing the path first. Giving it a number key makes the same choice.
Each checkout gets a new directory of its own, named after the repository and numbered (`farhelm-1`, `farhelm-2`, and so
on), or named after the repository and the session if you gave the session a name (`farhelm-fix`). **Folder** switches
back to an ordinary directory.

**Clone** on a session in a managed checkout starts a managed checkout of the same repository, even if the session runs
in a subdirectory. The name starts as the source's name plus `-clone`, then `-clone-2`, `-clone-3`, and so on when
taken. Editing the name keeps exactly the name you enter and reports a conflict if its directory is taken. **Folder**
restores the source's directory and name; for a new sandbox or container it stays at the home directory.

**Replace with** starts on **Folder** at the source session's directory. If the session uses a managed checkout, keeping
that directory keeps your changes, and the launcher names the checkout. Choose **Managed checkout** to start from a fresh
clone without those changes; the warning in **Destination** then says what happens to the old checkout: when you replace
the last session using it, it moves to the host's trash. In a sandbox or container, that trash stays inside and is
deleted with the sandbox or container. **Replace** keeps the existing directory.

When no [prepared checkout](/docs/using/start-a-session/#prepared-checkouts) is ready, Git brings the host's cache of the repository up to date, then clones the default branch in the
session's terminal. The agent starts once that finishes. Both commands use the host's own Git credentials, so anything
Git asks for, such as a password, shows up in the terminal for you to answer. A private repository without a credential
helper can ask twice. If either command fails, the session's status shows error, the terminal says what went wrong,
and any partial clone stays where it is.

In a [container session](/docs/agents/containerized-sessions/) or
[Tensorlake sandbox](/docs/using/tensorlake-sandboxes/#managed-checkouts), private repositories need a
GitHub token that the host's recipe selects from **Settings → Credentials**; public repositories need none.

The cache makes repeated managed checkouts faster and takes roughly the disk space of one extra copy of each repository
on each host. It lives under Farhelm's state directory on that host, in `repo-cache/<owner>/`, outside your checkout
directory: each rebuild of a cache gets a directory of its own, named `<name>.git:gen-` and an identifier, and a small
`<name>.git:current` file names the one in use. Farhelm removes caches unused for more than 30 days when the host's supervisor, the program that
keeps its sessions running, starts (see [The pieces](/docs/how-it-works/the-pieces/)). You can delete a cache directory
by hand at any time; existing checkouts stay independent, and the next managed checkout downloads it again. Avoid doing
that while a checkout is being prepared, since it can make that launch fail, and leave the sibling `.lock` files in
place so concurrent checkouts still take turns. Git tidies the cache in the background after a launch rather than in
its terminal; another launch of the same repository may wait while that finishes. A cache failure names its path in
the terminal and stops the clone.

An agent on an ordinary host can also start a session in a new managed checkout when you ask it to, with your
approval ([Approve what agents do](/docs/using/approve-agent-requests/)).

On ordinary hosts, first tell Farhelm which directory new checkouts go into. Until you have, choosing **Managed
checkout** asks for it:

<Screenshot
  name="start-a-session/checkout-setup"
  alt="The launcher in managed checkout mode asking for the checkout folder, with the field and its save button explained."
/>

This sets the default for hosts without a directory of their own. To change it later, or save an empty field to clear it,
use **Default checkout folder** under **Checkouts** in **Settings**,
opened from the gear at the foot of the [navigation rail](/docs/using/manage-hosts/), the column of icons down the left
edge of the sidebar.

The same section has a **Post-clone command** field for a shell command to run in each new clone, on its host, before the
agent starts (installing dependencies, say). Save it explicitly; empty the field and save to remove it. Changes affect
future checkouts only.

### Prepared checkouts

By default, Farhelm keeps one extra checkout ready for each repository you launch on each host. The next launch updates
that earlier clone from GitHub instead of cloning again, avoiding much of the local work. Its terminal says when it
uses an earlier checkout. The **Keep a checkout ready for faster launches** switch is under **Checkouts** in
**Settings**.

The extra checkout uses disk space in `.farhelm-spares` inside your checkout directory, in addition to the repository
cache. Farhelm prepares it through your login shell, without a terminal or credential prompts, at low CPU priority for
at most about ten minutes. If credentials need you to type something, or preparation fails, the next launch can clone
normally in its terminal. Your post-clone command still runs only when you launch, in the session's final directory.

This is a clone made earlier and then updated. Unchanged files keep older modification times, and Git's reflog records
the earlier clone and update. `FETCH_HEAD` and `ORIG_HEAD` exist, and objects from deleted branches can remain until Git
cleans them up. Git hooks and checkout filters, including Git LFS, run when the extra checkout is prepared in another
directory, then only for the update in the final directory. That update runs `post-merge` rather than `post-checkout`.

If the branch was deleted upstream, or rewound or rewritten so that it no longer contains the prepared checkout's
commit, Farhelm clones normally. Git 2.48 and later also notices a changed default branch; older capable Git may use the
original default branch until the next spare is prepared. Any other failed update stops the launch and shows its error
instead of starting another clone and asking for credentials again.

Turning the switch off affects future creates. Each repository's prepared checkout is discarded at its next create on
that host. Choosing a different checkout directory likewise discards the old spare when you next create a checkout of that
repository. Unused spares go with the repository cache after 30 days. Leave `.farhelm-spares` to Farhelm;
[uninstalling](/docs/get-started/uninstall/) keeps it alongside your other checkout data.

### Checkout management

Each host can have a checkout directory of its own in its [settings](/docs/using/manage-hosts/#host-settings).
An empty **Checkout folder** uses the default from **Settings → Checkouts**; **Use default** restores that choice.
Changing the default affects each host without its own directory at its next launch, including hosts already added.
Existing checkouts stay where they are.

The post-clone command applies to every host. To give one host a command of its own, run
`farhelm helm checkout-config` on the machine where you run the Farhelm app, whose built-in helm keeps your checkout
settings (see [The pieces](/docs/how-it-works/the-pieces/)); `farhelm helm checkout-config --help` lists the options.
A host given its own command there keeps it whatever **Settings** says.

Farhelm owns the managed checkouts it makes, the directory they go into, their prepared checkouts and their trash. Work in a checkout as usual,
but do not restore a backup or filesystem snapshot over them, and keep them on an ordinary filesystem rather than one
like FAT: Farhelm does not detect such changes.

## Workspace trust

Farhelm grants workspace trust when you start a sandbox session or container session with Claude Code, Codex, Muse
Code, Pi or Antigravity. Your custom Antigravity settings still take precedence. On installed hosts and hosts you
create with **Add host**, trust follows **Settings → Agents**.

Codex, Muse Code and Pi have their own trust switches, all off by default. Each applies to directories you choose
and to managed checkouts. Enabling one lets the repository's hooks, settings and
commands run as if you had approved them. Farhelm passes an argument for the launch and the agent keeps its saved
configuration. The switches apply to the launcher's **Agent** tab. [Custom commands](/docs/agents/custom-commands/)
supply their own arguments.

See [Antigravity workspace trust](/docs/agents/antigravity/#workspace-trust) for that agent's switch.

The destination's trust policy applies when you start a session or use **Clone**, **Restart with** or **Replace with**.
Plain **Restart** and **Replace** reuse the trust carried by the saved launch. See
[Stop, restart, and resume](/docs/using/stop-restart-resume/) for those actions. Muse's YOLO mode grants trust regardless
of its switch. Pi's switch approves project settings and extensions; Pi still runs the agent's actions without asking.

On the **Claude Code** page, you can **Answer Claude's "trust this folder?"**. The switch is off by default. It applies
when you choose Claude Code in the **Agent** tab or approve another agent's request to start Claude Code. This includes
Claude Code sessions that start in a new managed checkout. Farhelm protects your home directory and its parents, including the filesystem root,
because Claude's trust would cover everything inside. In a sandbox or container session, the default Claude config
can already trust the disposable host's home. A launch there uses that entry. A different Claude config or an existing
choice to leave home untrusted can still leave the question visible. If Farhelm cannot resolve your home
directory on the session's host, the terminal shows a note and Claude may ask as usual.

Farhelm edits the Claude settings that the login shell selects on the session's host, normally `~/.claude.json`.
A wrapper that changes the directory or selects a different Claude configuration can still leave Claude asking.
If the edit was for the first launch in a new managed checkout, Farhelm tries to remove the key when the checkout
moves to the trash. Trust added when you launch Claude Code in an existing directory stays after the session ends. The
edit is best effort.
A Claude session exiting at the same instant can lose either program's update, and an update to Claude can change how
the file works. Read the caution in Settings before turning it on. Trust lets the repository's Claude hooks and commands
run, as when you answer Yes.

When Claude, Codex, Muse or Antigravity asks its trust question in a session started from the **Agent** tab, a note
appears above the terminal if that agent's switch is off. Claude's note can also appear when another agent starts a
Claude Code session. Its **Settings** button
(**Settings and caveats** for Claude) opens the agent's Settings page at its trust switch. × hides the note
until the question leaves the screen, and **Don't show again** stops that agent's note for every session, leaving the
other agents' notes alone. To bring one back, turn on the hint switch on the agent's page. You still answer
the current question in the terminal. Pi has a trust switch without a hint.

## When a launch fails

What you see depends on how far the launch got. When Farhelm can tell before starting anything that the launch will not
work, for example because the directory does not exist on that host, Farhelm cannot enter it, or the host just went
offline, it shows the reason
in a **Not launched.** alert under the launcher's buttons and keeps your choices, so you can fix it and launch again.
No session is created. When
the agent itself fails to start, for example because it is not installed on that host, the session is created and its
status shows error; the agent's page in [Supported agents](/docs/agents/) says what to install. An agent that starts and
then quits shows exited. [Read the session list](/docs/using/session-list/) explains each status.

A launch on a suspended [sandbox](/docs/using/tensorlake-sandboxes/#suspend-and-resume) resumes it first, and a launch
on a stopped container starts it first. The launcher closes, and a small status at the bottom of the window says the
host is resuming or starting and that the session starts when it is ready; you can keep working meanwhile. This works
the same for **Restart with**, **Replace with** and a [quick launch](/docs/using/launch-templates/#quick-launch). If the
host cannot be resumed, is suspended again before it reconnects, or does not reconnect within about a minute, the
launcher comes back with your choices and says the session was not launched.

If the host does not answer within 20 seconds, the launcher comes back without **Not launched.** and says the request is
still being carried out: the session may still start and appear in the session list. Your choices stay in the launcher.

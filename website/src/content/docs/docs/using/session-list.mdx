The session list shows every session on every host, and what each agent is doing right now, so you can tell which one
needs you without opening any of them.

<Screenshot
  name="session-list/row"
  alt="One row of the session list, with its status, agent and permissions mark, and host and directory explained."
/>

The age at the right of a row says how long ago the session last did something: `now`, `<1m`, `5m`, `1d`. Select a row
to open its terminal beside the list. Hovering over the dot or the marks beside the title says what each one means.

## What the statuses mean

<Screenshot
  name="session-list/statuses"
  alt="The session list with a waiting session, an idle unread session, and an ended session each explained."
/>

Waiting is the status worth watching for: the agent has stopped to ask you something, such as approving a command, and
does nothing until you answer. Not every agent can tell Farhelm when it is waiting; [Supported agents](/docs/agents/)
says which ones can.

An agent can also be waiting on Farhelm itself, when it asks to start, stop, or change a session with the `farhelm`
command. That request shows as a card in the corner of the window, not in the session list, and you answer it on the
card; [Approve what agents do](/docs/using/approve-agent-requests/) covers it.

A session that has ended says how in words under its name, instead of a coloured dot (with **compact** ticked, as an
icon you can hover over):

- **exited**, with the agent's exit code. "stopped by user" is added when you stopped it.
- **interrupted**: the host rebooted, which ended the agent. The session waits for you to start it again.
- **error**: the agent could not start; the reason follows the word. An agent that starts and then quits shows exited.

An exited session's terminal stays readable for as long as its host stays up. A reboot clears it, so an interrupted
session has no terminal until you start it again. [Stop, restart, and resume](/docs/using/stop-restart-resume/) covers
starting either kind again.

## Find a session

<Screenshot
  name="session-list/controls"
  alt="The compact checkbox, the host filter, and the sort order above the session list, each explained."
/>

The number beside **SESSIONS** counts every session; with a host filter on, it says how many of them match. There is no
search box; with many sessions, filter by host and sort by title.

## Rename it, or mark it read

<Screenshot
  name="session-list/row-menu"
  alt="A session's menu, opened from the row's three dots, with rename and mark read explained."
/>

Clicking the blue dot does the same as **mark read**. The rest of the menu clones, replaces, stops, or deletes the
session, and is covered in [Stop, restart, and resume](/docs/using/stop-restart-resume/).

## When a row shows a bell

A bell appears on a row, just left of its age, when Farhelm has noticed something about that session that you can act
on. For now these are all about following the agent's conversation, which is what lets **restart** pick that
conversation up again later. For example, the agent has been working for a while and never told Farhelm which
conversation it is in, so **restart** cannot pick it up. Each notification says what happened and what you can do about
it, such as starting the session over with **replace with**, or, when nothing can be done, what you lose.

A red, filled bell means at least one notification is new. Click it to list them, newest first, with the ones you have
not seen before marked **new**. Clicking the bell does not open the session. Closing the list, by clicking elsewhere,
pressing Escape, or clicking the bell again, marks everything in it read, and the bell turns grey. **clear all** removes
them, and the bell goes away until something new happens. Read and cleared notifications are the same in every window
connected to the same [helm](/docs/how-it-works/the-pieces/), and a session keeps only its 10 most recent ones.

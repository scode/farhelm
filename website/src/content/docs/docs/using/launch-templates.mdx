A launch template is a set of [session launcher](/docs/using/start-a-session/) choices saved under a name. It holds
only the choices you put in it, so templates combine: one can pick your usual agent and model, another the host and
directory of a project, and applying both sets up the whole launch.

## Make a template

<Screenshot
  name="launch-templates/templates-button"
  alt="The templates button beside new above the session list, which opens the templates panel."
/>

<Screenshot
  name="launch-templates/panel"
  alt="The Templates list: choose a template to edit it, or use + new template to start another."
/>

Choose **+ new template**, give it a unique name, then choose **switches launcher to**: **agent**, **command**, or
**don't switch**. An agent or command template opens that tab when you apply it. **don't switch** keeps the current tab
and offers only the host, destination, and session name.

Use **+ add field** for each choice the template should make, then **save**. Only the fields shown under **sets** are
applied; a field you remove with **✕** is left alone. A **default** value resets that choice to the agent's default,
which is different from leaving it out. An empty model input means the default model; otherwise you can type any model,
with suggestions when the template sets an **agent type**. Approvals and other offered choices follow that agent type.

The destination can be a directory or a
[fresh GitHub checkout](/docs/using/start-a-session/#start-from-a-fresh-github-checkout). A model or a destination can
stand on its own: another template can supply the agent or host.

Templates belong to the helm, the program that shows you every host's sessions
([The pieces](/docs/how-it-works/the-pieces/)), so every window and every host sees the same ones. A template that sets
a command still needs that command to exist on the host you launch on.

## Save a setup from the launcher

When you have set up a launch in **new** or **clone**, choose **save as template**. Give it a new name and check the
choices you want to keep. Agent, model and effort choices are checked when set, as are command choices. Approvals and
workspace trust are checked when you chose them; a host, directory and session name only when you picked or typed them.
A fresh GitHub checkout's repository is checked too. Remembered defaults and a cloned session's host and directory
stay available, but unchecked.

The template keeps the current **agent** or **command** tab and only the choices you check. Saving closes the launcher
and opens the new template for editing in the Templates panel. A name already in use is refused; choose another name.
**cancel** or Escape returns to the setup without saving. This action is not offered in **replace with**.

## Edit a template

<Screenshot
  name="launch-templates/edit-form"
  alt="codex-deep selected for editing, with its agent switch, Codex, model, effort, add and remove controls, and save button."
/>

Choose a template's row to open its editor. **duplicate** opens an unsaved copy with a new name. Changes are saved only
when you choose **save**; leaving an edited template asks whether to save, discard, or keep editing. At phone width, **‹
templates** returns to the list.

Changing **switches launcher to** or the **agent type** can make a field that is already set no longer fit. It stays
visible with a message: change or remove it before saving. A stored template that sets agent or command choices
but has no saved tab choice opens with that tab chosen and marked as **unsaved changes**; saving stores that choice,
while discarding keeps the template applying as before.

**delete** removes a template immediately. The **undo** notice lasts about ten seconds while the panel stays open;
choose it to restore the template, provided another template has not taken its name.

A session remembers the choices it was launched with, not which templates supplied them, so editing or deleting a
template never changes a session that already started from it.

## Apply templates in the launcher

<Screenshot
  name="launch-templates/apply"
  alt="The launcher's search box with tl: typed, listing the three templates."
/>

<Screenshot
  name="launch-templates/applied"
  alt="The launcher after applying codex-deep and then api-repo, launching Codex on build-box in ~/src/api."
/>

Templates apply in the order you choose them, and where two set the same choice, the later one wins. A template only
fills in what it holds, so anything the launch still needs, such as the agent when no template picked one, you choose
by hand as usual.

A template whose choices do not fit what the launcher holds is refused as a whole, with a message saying which choice
did not fit: a model the chosen agent does not offer, for example, or an older template with a model and no saved tab
choice while the launcher is on its **command** tab. In **replace with**, where the host is fixed, a template
that sets a host is refused the same way. **restart with** does not offer templates at all.

## Templates and your agents

Agents in your sessions can apply templates too, when they start sessions of their own with the `farhelm` command:

```sh
farhelm agent create --template codex-deep --template api-repo
```

Here `api-repo` supplies the host and directory, so the command needs neither `--host` nor `--cwd`. Other options such
as `--model` act as further changes after the templates, and `farhelm agent templates` lists the templates and what each
sets.

A few templates work in the launcher but not for agents. The `farhelm` command cannot make a fresh GitHub checkout, so a
template with that destination is refused there unless `--cwd` gives a directory instead. `farhelm spawn` always starts
on the agent's own host, so it refuses a template that sets a host. And on a host that asks before YOLO launches, an
agent cannot use a template that makes the launch YOLO or a custom command
([Approve what agents do](/docs/using/approve-agent-requests/#yolo-sessions-and-custom-commands)).

Agents can also create, edit, and delete templates with `farhelm agent template create`, `edit`, and `delete`.
Each change shows you the whole template on a card first, command line included, and happens only if you allow it,
unless you have told Farhelm not to ask for that agent's host ([Approve what agents
do](/docs/using/approve-agent-requests/)). An agent's edit cannot remove a choice from a template, so it never drops a
command line the agent could not see.

NOTE: Templates are not a place for secrets. Every host your helm manages can read every template, command lines
included.

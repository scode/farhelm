A launch template is a set of [session launcher](/docs/using/start-a-session/) choices saved under a name. It holds
only the choices you put in it, so templates combine: one can pick your usual agent and model, another the host and
directory of a project, and applying both sets up the whole launch.

## Make a template

<Screenshot
  name="launch-templates/templates-button"
  alt="The templates button beside new above the session list, which opens the templates panel."
/>

<Screenshot
  name="launch-templates/panel"
  alt="The Templates list: choose a template to edit it, or use + new template to start another."
/>

Choose **+ new template**, give it a unique name, then choose **switches launcher to**: **agent**, **command**, or
**don't switch**. An agent or command template opens that tab when you apply it. **don't switch** keeps the current tab
and offers only the host, destination, and session name.

Use **+ add field** for each choice the template should make, then **save**. Only the fields shown under **sets** are
applied; a field you remove with **✕** is left alone. A **default** value resets that choice to the agent's default,
which is different from leaving it out. An empty model input means the default model; otherwise you can type any model,
with suggestions when the template sets an **agent type**. Approvals and other offered choices follow that agent type.
Without an agent type, every approval choice is offered, and applying the template is refused if the chosen agent does
not offer that choice.

An agent template can also set a **wrapper prefix**. Type the words that go before Farhelm's agent command, or leave
the field empty to explicitly run without a wrapper. Removing the field with **✕** leaves the launcher's current prefix
alone, including its remembered value. See [Agent wrappers](/docs/agents/agent-wrappers/) for the pass-through rules and
why a prefix should not contain secrets.

To reuse a first message, add **initial prompt** and type it into the multiline box. Each new session started from the
template receives that message; you can edit it in the launcher before starting. The field is offered for agents that
accept an initial prompt, or while the template leaves the agent type unset. It is not offered for command templates.

The destination can be a directory or a [managed checkout](/docs/using/start-a-session/#start-from-a-managed-checkout),
chosen with the same **folder** and **managed checkout** control as the launcher. The editor explains that each session
gets its own checkout and that its directory moves to the trash when its last session is deleted. A model or a
destination can stand on its own: another template can supply the agent or host.

A **session name** can be a **base name** or a **fixed name**. When you apply a base name in the session launcher or a
quick launch, or an agent starts a session from the template, a managed checkout uses it as-is when free, then adds `-2`, `-3`, and so on up to `-50` when taken. The
session and its checkout directory get the same number, so you can launch the same setup repeatedly. A fixed name
reports a clash instead. Names in existing templates are base names; a launch into an ordinary directory uses either
kind as-is.

Workspace trust comes from [managed-checkout settings](/docs/using/start-a-session/#trust-in-managed-checkouts). A trust
choice saved in an older template is ignored and is removed when you save that template again.

Templates belong to the helm, the program that shows you every host's sessions
([The pieces](/docs/how-it-works/the-pieces/)), so every window and every host sees the same ones. A template that sets
a command still needs that command to exist on the host you launch on.

## Quick launch

Mark a template with **⚡** to start it with Cmd+P on a Mac, or Ctrl+Shift+P elsewhere. The session starts and is selected
without opening the session launcher. Only one template is marked: another bolt moves the mark, and the lit bolt clears
it. An **agent** template needs an agent to be marked; a **command** template needs a nonblank command. With **don't
switch**, it is judged as an agent launch.

Choices the template leaves out use **new**'s defaults, including the open session's host and directory. A template can
start a fresh [managed checkout](/docs/using/start-a-session/#start-from-a-managed-checkout) this way too: marking it
means you choose to create its new directory without first seeing the path. If Farhelm asks about YOLO or the launch
fails, the session launcher opens with that setup and the question or error. With no marked template, the shortcut opens
Templates to help you choose one. Renaming keeps the mark; deleting clears it, and **undo** restores only the template.

The quick switcher's **Quick launch** row does the same thing. In Firefox, Ctrl+Shift+P may open a private window instead;
use that row there. While the session launcher is open, the shortcut applies the marked template to the draft and leaves
**Launch** to you. Other dialogs keep their keyboard shortcuts.

To start any template by name, press Cmd+J on a Mac or Ctrl+Shift+J elsewhere. This opens a template-only list: type part
of a name, use ↑ and ↓ to choose, then press Enter. If you type the exact name, that template is highlighted. Each row
shows its saved choices and any **⚡** or number shortcut. A template that needs more choices opens the session launcher
for you to finish, with a banner saying it needs more choices. The same banner appears if your marked template no
longer has what it needs to launch. Escape closes the list and returns focus to where you were. Cmd+J does nothing while another dialog
is open, including the session launcher.

The desktop app accepts this shortcut. In a browser, the browser may keep it: [Chrome](https://support.google.com/chrome/answer/157179?hl=en_1), [Edge](https://learn.microsoft.com/en-us/microsoft-edge/devtools/shortcuts/), and [Firefox](https://support.mozilla.org/en-US/kb/keyboard-shortcuts-perform-firefox-tasks-quickly) list Ctrl+Shift+J for a console on Windows and Linux; Firefox lists Cmd+J for Downloads on a Mac. The browser's shortcut lists do not establish whether Farhelm receives the key.

After a quick launch, Rename opens with the session's name selected while the agent is already starting. Enter keeps
the name; typing replaces it, and Enter saves it. Escape or **cancel** keeps the name too. Closing Rename takes you to
the new terminal. This also happens for number shortcuts, combined launch sequences and the Cmd+J list, even when a template supplied
the name. If the session launcher opened first, it already offered the name field and Rename does not open again.

In Settings, beside **skip session confirmations**, **name sessions on quick launch** turns this off. It is on by
default, and the choice is shared by every window using your helm. Naming a session this way leaves its managed
checkout's directory unchanged: a directory created as `repo-N` keeps that name.

## Number shortcuts

Give a template a number key with the key button beside its **⚡**. Cmd+0–9 in the Mac app, or Ctrl+Shift+0–9
everywhere else (including a browser on a Mac), starts that template directly, with the same defaults and YOLO questions
as [quick launch](#quick-launch). The key is the number's position on your keyboard; it does not use the numeric keypad.

Each key belongs to one template, and a template has one key at most. Picking an occupied key moves it to this template;
**no shortcut** removes it. Number keys and **⚡** are independent, and every window shares your bindings. Rename keeps
the key; delete frees it, and **undo** restores only the template. Pressing an unbound key from the session list opens
Templates to help you set one. With the session launcher open, a bound key applies its template to your draft; an
unbound key shows a message there. Other dialogs keep the keyboard.

Any template can hold a number key, even one that only changes a model or directory. Pressed alone, a partial template
opens the session launcher with its choices applied and a brief banner explaining how to combine it with other
templates. Complete the setup there, or close it and use a [launch sequence](#combine-templates-from-the-keyboard).
The **⚡** mark still needs a template that can launch on its own.

Giving a template a number key also chooses to create any managed checkout it names without showing the path first,
just as marking it with **⚡** does.

## Combine templates from the keyboard

Press Cmd+X in the Mac app, or Ctrl+Shift+X everywhere else, then the number keys for the templates you want, then Enter.
For example, Cmd+X, Cmd+1, Cmd+5, Enter starts key 1's setup with key 5's choices applied on top. Inside the sequence,
bare number keys work too, and the usual quick-launch chord adds your **⚡** template. Later templates win where their
choices overlap, just as when you [apply templates in the launcher](#apply-templates-in-the-launcher).

A larger amber pill in the middle of the terminal shows what you have queued, with a brief entrance and a soft glow.
With no session open it sits in the middle of the main area; while the launcher is open it stays at the bottom so you
can keep editing. There is no timeout. Escape cancels; clicking,
switching windows or opening a dialog cancels too. Any other key cancels and goes to its usual target, so you can go
straight back to typing in the terminal. Enter with no templates queued cancels. Outside the session launcher, text
fields keep Cmd+X for Cut, or the browser's usual Ctrl+Shift+X behavior. In the launcher's own fields, a selection keeps
that normal action; without selected text, the prefix starts a sequence.

The combined setup starts directly, with the same defaults and YOLO questions as [quick launch](#quick-launch). If a
template does not fit, the session launcher opens and names the template and choice that need attention. If the combined
choices still do not make a complete setup, a banner says to complete it there. An unbound
number opens Templates when you press Enter. With New, Clone or Replace with open, Enter applies the queued templates
to that draft instead of starting a session. The pill says **apply** there; an unbound key or template that does not fit
shows a message beneath search and leaves that press's edits unapplied. Single number shortcuts and **⚡** still start
immediately from the session list without the prefix.

## Save a setup from the launcher

When you have set up a launch in **new** or **clone**, choose **save as template**, beside **reset choices**.

<Screenshot
  name="launch-templates/save-as-template"
  alt="The save as template panel with a name typed and the agent and effort checked, with the name, checkboxes, and save explained."
/>

Agent, model and effort choices are checked when set, as are an initial prompt you typed and command choices. Approvals
and a wrapper prefix are checked when you chose them; a host and directory only when you picked or typed them. A session
name is checked after you type it or apply a template that sets it.
A selected managed checkout's repository is checked too; unselected repository text is left out. Remembered defaults and
a cloned session's host and directory stay available, but unchecked.

The session-name row offers **base name** and **fixed name** too. A name you typed starts on base; a name supplied by
a template keeps that template's choice. Saving a numbered base keeps the original name: `app-review-2` is saved as
`app-review`, ready to find the next free checkout when you use it again.

The template keeps the current **agent** or **command** tab and only the choices you check. Saving closes the launcher.
**cancel** or Escape returns to the setup without saving. This action is not offered in **replace with**.

## Edit a template

<Screenshot
  name="launch-templates/edit-form"
  alt="codex-deep selected for editing, with its agent switch, Codex, model, effort, add and remove controls, and save button."
/>

Choose a template's row to open its editor. **duplicate** opens an unsaved copy with a new name. Changes are saved only
when you choose **save**; leaving an edited template asks whether to save, discard, or keep editing. At phone width, **‹
templates** returns to the list. Hidden formatting characters in a template's fields show as visible
codes, and such a field cannot be edited in place: remove it with **✕** and add it again. A template whose session name
or command contains hidden or control characters still launches, but Farhelm refuses to save changes to it until you
replace those fields. This includes joined emoji in a session name.

Changing **switches launcher to** or the **agent type** can make a field that is already set no longer fit. It stays
visible with a message: change or remove it before saving. A stored template that sets agent or command choices
but has no saved tab choice opens with that tab chosen and marked as **unsaved changes**; saving stores that choice,
while discarding keeps the template applying as before.

**delete** removes a template immediately. The **undo** notice lasts about ten seconds while the panel stays open;
choose it to restore the template, provided another template has not taken its name. An older template that no longer
meets today's rules for saving shows **delete permanently** instead, and cannot be restored.

A session remembers the choices it was launched with, not which templates supplied them, so editing or deleting a
template never changes a session that already started from it.

## Apply templates in the launcher

<Screenshot

/>

<Screenshot

  alt="The launcher after applying codex-deep and then api-repo, launching Codex on build-box in ~/src/api."
/>

Templates apply in the order you choose them, and where two set the same choice, the later one wins. A template only
fills in what it holds, so anything the launch still needs, such as the agent when no template picked one, you choose
by hand as usual.

You can also press the **⚡** shortcut, a bound number key, or a completed launch sequence while New, Clone or Replace
with is open. Several presses stack in order, and **Launch** remains your action. Your current field and search text
stay in place unless a template switches tabs and removes that field; focus then returns to the launcher's search.

A template whose choices do not fit what the launcher holds is refused as a whole, with a message saying which choice
did not fit: a model the chosen agent does not offer, for example, or an older template with a model and no saved tab
choice while the launcher is on its **command** tab. In **replace with**, where the host is fixed, a template
that sets a host is refused the same way. **restart with** does not offer templates at all.

## Templates and your agents

Agents in your sessions can apply templates too, when they start sessions of their own with the `farhelm` command:

```sh
farhelm agent create --template codex-deep --template api-repo
```

Here `api-repo` supplies the host and directory, so the command needs neither `--host` nor `--cwd`. Other options such
as `--model` act as further changes after the templates, and `farhelm agent templates` lists the templates and what each
sets.

An agent can start a fresh managed checkout with a template too, or give `farhelm agent create --gh acme/web` directly
(`--github` is an alias). `--title "Fix parser"` names its directory `web-fix-parser`; without a title Farhelm picks
the next free `web-N`. The approval card shows the repository and exact directory before starting it.

`farhelm spawn` always starts on the agent's own host and never makes a fresh checkout, so it refuses a template that
sets a host or a managed checkout. `farhelm agent clone` copies the source's existing directory and takes no repository
option. On a host that asks before YOLO launches, an agent cannot use a template that makes the launch YOLO or a custom
command ([Approve what agents do](/docs/using/approve-agent-requests/#yolo-sessions-and-custom-commands)).

Agents can also create, edit, and delete templates with `farhelm agent template create`, `edit`, and `delete`.
Create and edit accept `--gh`/`--github` for a managed checkout, or `--cwd` for an existing directory, and
`--title-kind base` or `fixed` to choose the kind of session name.
They can assign **⚡** with `--quick-launch` or a number with `--key 1` (using any digit from 1–9 or 0). An edit can
remove this template's mark or key with `--no-quick-launch` or `--no-key`, even without changing its other choices.
Assigning a mark or key that belongs to another template moves it; the card tells you which template loses it.
The **⚡** mark needs an agent for an **agent** template or a nonblank command for a **command** template; without a
saved launch kind, it needs an agent. A number key can select a partial template.
`farhelm agent templates` shows these assignments alongside each template's choices.
Each change shows you the whole template on a card first, command line included, and happens only if you allow it,
unless you have told Farhelm not to ask for that agent's host ([Approve what agents
do](/docs/using/approve-agent-requests/)). A change that leaves a wrapper prefix in a template always asks, on every
host, because later launches from it treat the prefix as yours. An agent's edit cannot remove a choice from a template, so it never drops a
command line the agent could not see.

NOTE: Templates are not a place for secrets. Every host your helm manages can read every template, command lines
included.

## Why should I use it?

<dl class="farhelm-why">
<div><dt>The agent's own TUI</dt><dd>You drive the real Claude Code, Codex, or whatever you run, keystroke for keystroke, not a wrapper around it.</dd></div>
<div><dt>Screenshots and files</dt><dd>Paste or drop one into the terminal and the agent has it, even when the agent runs on a machine across the network.</dd></div>
<div><dt>Downloads</dt><dd>When the agent mentions a file it made, hover over the path and click to download it.</dd></div>
<div><dt>Nothing loses its place</dt><dd>Close the laptop, restart Farhelm, reboot the remote host: every session is still in the list, and restarting it picks the agent's conversation back up.</dd></div>
<div><dt>Templates</dt><dd>Often start Codex in YOLO mode on a checkout of <code>acme/web</code> on <code>build-box</code>? Save that as a <a href="/docs/using/launch-templates/">launch template</a>, then in the Mac app press Cmd+N, type <code>tl:web</code>, and press Enter twice: once to apply it, once to launch.</dd></div>
<div><dt>Change one thing</dt><dd>Want this session again, but with Codex instead of Claude? <strong>clone</strong> opens the launcher with everything already filled in, so you change just the agent and launch. <strong>replace with</strong> does the same, and swaps the new session in for this one.</dd></div>
<div><dt>Agents start sessions</dt><dd>Tell your agent <code>$farhelm for each of the TODO items above, start a session in a new managed checkout of acme/web, named after the item</code>, and it will. Farhelm <a href="/docs/using/approve-agent-requests/">asks you</a> before each one starts, unless you have told it to trust that host.</dd></div>
<div><dt>Version control</dt><dd>Farhelm works in any directory, whatever it uses for version control. It can also <a href="/docs/using/start-a-session/#start-from-a-managed-checkout">manage checkouts</a> of your GitHub repositories: a fresh clone for each session, moved to the trash when you are done with it.</dd></div>
</dl>

## How it works

<ThemedImage
  light={howItWorksLight}
  dark={howItWorksDark}
  alt="How Farhelm works: the helm on your laptop lists every session from every host and reaches a supervisor on each remote box over ssh; the selected session's real terminal fills the pane"
/>

Farhelm has two parts. The **helm** is what you look at, usually the Farhelm app on your Mac: it keeps your list of hosts
and shows every session. A **supervisor** runs on each machine, your Mac included, and keeps that machine's agents and
their terminals running ([the pieces](/docs/how-it-works/the-pieces/)). The helm reaches each supervisor over SSH.
Nothing listens on a network port, nothing goes through a relay ([security model](/docs/how-it-works/security-model/)),
and every box in the diagram can restart without losing a session
([what survives what](/docs/how-it-works/what-survives-what/)).

## Is this thing vibe coded?

No. *However*, this *did* start out - and still is - an experiment in developing a real product with non-trivial
complexity while utilizing zero human code review. I intend to write more in depth about it, but the short of it is that
through a number of practices (various forms of adversarial code review, continuously narrowing down SPEC guard rails,
human architectural oversight), my assessment is that overall quality is higher (not perfect!) than the manually coded
version would be - besides the fact that it would not exist, because I wouldn't have had the time to make it!

You will definitely notice signs of AI. I'm not optimizing for hiding the fact that
AI is involved, I am optimizing for solving the problem with an acceptable quality bar.

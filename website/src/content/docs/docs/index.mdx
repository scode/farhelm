## How it works

<ThemedImage
  light={howItWorksLight}
  dark={howItWorksDark}
  alt="How Farhelm works: the helm on your laptop lists every session from every host and reaches a supervisor on each remote box over ssh; the selected session's real terminal fills the pane"
/>

One **helm** is the control plane: it holds the host list, serves the UI, and connects straight to a **supervisor** on
each host over SSH. The supervisor owns the agents' real terminals and their state ([the pieces](/docs/how-it-works/the-pieces/)).
Nothing listens on a network port, nothing goes through a relay ([security model](/docs/how-it-works/security-model/)),
and every box in the diagram can restart without losing a session
([what survives what](/docs/how-it-works/what-survives-what/)).

## Is this thing vibe coded?

No. *However*, this *did* start out - and still is - an experiment in developing a real product with non-trivial
complexity while utilizing zero human code review. I intend to write more in depth about it, but the short of it is that
through a number of practices (various forms of adversarial code review, continuously narrowing down SPEC guard rails,
human architectural oversight), my assessment is that overall quality is higher (not perfect!) than the manually coded
version would be - besides the fact that it would not exist, because I wouldn't have had the time to make it!

If you're turned off by anything that looks AI-generated, this isn't for you. I'm not optimizing for hiding the fact that
AI is involved, I am optimizing for solving the problem with an acceptable quality bar.

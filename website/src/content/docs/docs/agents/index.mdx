Farhelm runs any coding agent in a session, but how much it adds on top depends on the agent. The matrix below is the
big picture: what Farhelm does for each agent it knows, and for anything else you run as a
[custom command](/docs/agents/custom-commands/). Claude and Codex get the most; the others get less, in different
ways. Each agent also has its own page, linked from its name in the matrix, with setup steps and gotchas specific to
that agent when it has any.

Some things work the same for every agent and every command, so they have no row: the session keeps running when you
close the window, [clone and replace with](/docs/using/stop-restart-resume/) carry its setup over, pasting screenshots
and files [works](/docs/using/work-in-a-session/#copy-paste-and-links), and so do downloads from the terminal.

## Permission modes

Choose **custom** to supply your own permission flags for Claude, Codex, Grok, Muse, Cursor or OMP. They replace
Farhelm's permission flags; you are responsible for making sure they only change permissions. Farhelm does not check
what they do, so the session gets the amber YOLO shield and hosts that ask before YOLO launches still ask.

The field accepts quotes and backslash escapes to group words, without expanding variables or running commands. Its
preview shows the words passed to the agent. Templates save them; Clone, Replace with and Restart with let you edit
them, while a plain Restart reuses them. Custom is never remembered as the next launch's default permission. Goose,
Pi and OpenCode do not offer this choice. See [Start a session](/docs/using/start-a-session/).

**Guarded** lets an agent approve work on its own through a safety check that can still refuse an action or ask you.
It does not mean it asks about everything. **YOLO** skips those checks. The shield beside a session tells you which
choice Farhelm started it with; its hover names the agent's mode and the command it ran.

| Agent | Guarded mode | Flags Farhelm passes |
| --- | --- | --- |
| Claude | Auto mode: its classifier approves or blocks actions | `--permission-mode auto` |
| Codex | Sandboxed auto: workspace commands run in a sandbox; requests to leave it follow your approval policy | `-a on-request -s workspace-write` |
| Grok | Auto-review: its classifier approves or blocks actions | `--permission-mode auto` |
| Muse | Auto-review: its AI reviewer checks eligible actions, with a workspace sandbox | `--permission-profile :auto-review` |
| OMP | Write: workspace edits are approved automatically; other actions ask you | `--approval-mode write` |
| Cursor | Agent's own setting: Farhelm cannot override its configured Run Everything mode | No forcing permission flag |

Guarded is the default for every agent that offers it, unless you chose another mode or the launcher remembered one. Goose keeps its
approve, smart approve and chat choices and starts in YOLO unless you choose another mode;
Pi and OpenCode offer YOLO only. [Custom commands](/docs/agents/custom-commands/) use your own assertion about whether
the command is YOLO.

Farhelm passes these flags, but cannot guarantee the agent's behavior. Claude and Grok can allow actions through your
allow rules or hooks; Muse can loosen its sandbox or approval rules; OMP accepts project rules and plugins. For every
agent, always-allow answers, managed settings, plugins and switching modes inside the session can change what is
allowed, and the agent may change between versions. Check its own mode when that matters. A green shield describes
the launch choice, not a live audit of its actions.

Cursor's **agent's own setting** has a grey dashed shield. Hosts that ask before YOLO launches treat it as YOLO,
because Farhelm cannot promise a safety check. The same applies to older Claude, Codex, Grok and Muse sessions started without permission flags:
restart, plain Replace and copies keep their old command. Use **Clone**, **Replace with** or **Restart with** to build
a new guarded launch. On a host that asks first, plain Replace of an older session asks for confirmation too.

After this upgrade, [update your remote hosts](/docs/using/manage-hosts/) before starting sessions there. Launches saved
as guarded cannot be read by older Farhelm releases.

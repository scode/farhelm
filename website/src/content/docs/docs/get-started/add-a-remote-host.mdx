A remote host is a Linux machine or another Mac your Mac reaches over ssh. Once it is added, sessions can run there
just as they do on your Mac, and they keep running on the host while your Mac sleeps or Farhelm is closed.

**Add host** offers **SSH** for a machine you already have, and **Tensorlake sandbox** to create a cloud host from a
saved recipe. For the latter, follow [Tensorlake sandboxes](/docs/using/tensorlake-sandboxes/), which covers account
setup, billing and suspension. The rest of this page covers **SSH**.

## What the host needs

- Linux on an x86_64 or ARM (aarch64) machine, with systemd's services for your user account, which most distributions
  have; or an Apple-silicon Mac without the Farhelm desktop app installed. Intel Macs are not supported. Farhelm needs no
  root or sudo on either: everything it installs goes in your home directory.
- SSH access from your Mac. For a regular SSH host, Farhelm uses your keys, agent, and the Host names in
  `~/.ssh/config`. Check that destination by running `ssh <destination> true` in a terminal and completing any sign-in
  it asks for.
- Not BusyBox: hosts whose basic command-line tools come from BusyBox are not supported.
- Your Mac downloads Farhelm for the host and copies it over ssh. The download starts at get.farhelm.io, which hands
  the release files themselves over from GitHub, so your Mac needs to reach both. The host does not: it never needs
  access to get.farhelm.io or GitHub.

## Add it

Choose **+** (Add host) on the navigation rail, the column of icons down the left edge of the sidebar.

While Farhelm checks the destination over ssh, **Add** reads **Checking…**. The dialog also takes an optional alias:
the name Farhelm shows for the host instead of its destination, everywhere except the host's details. You can change
it later in the host's settings. An agent in one of your sessions can also ask to add a host. Its request waits as a
card, and **Open add dialog** on it opens this same dialog with the agent's destination and alias filled in
([Approve what agents do](/docs/using/approve-agent-requests/#host-changes)).

If you reach the host through Tailscale, turn on **Tailscale host** before choosing **Add**. Enter its Tailscale node
name or IP address, with your SSH login if needed, such as `dev@build-box`. Tailscale must be running on your Mac,
and the host must advertise the SSH key it uses. Farhelm uses those advertised keys to verify the connection.

If the host asks for a verification code, a password, or a key passphrase, enter it in **Add host**. With regular SSH,
you may also be asked to confirm an unfamiliar host key's fingerprint. Farhelm signs in once to check and set up the
host, then signs in again for sessions. The second question can appear after **Add host** closes. A security-key touch instruction appears
when SSH reports it. Keys held by your SSH agent can require a touch without a notice in Farhelm.

If Farhelm is already running on the host (you set it up before, say), the host is added as it is and the dialog
closes. If another Farhelm manages it, such as one on another computer, Farhelm first asks whether to **Take over**
the host, even with **Set up new hosts without asking** turned on. Taking over leaves the host's sessions running, and
the other Farhelm loses access to them until it takes the host back
([Take over a host from another Farhelm](/docs/using/manage-hosts/#take-over-a-host-from-another-farhelm)). Otherwise Farhelm asks first, listing each step setup would take on the host with the paths it uses. **Copy
plan** copies that list, and **Cancel** changes nothing on the host.

<Screenshot
  name="add-a-remote-host/setup-plan"

/>

Farhelm does not need tmux on the host. On a Linux host the list includes removing the copy of tmux that earlier
versions of Farhelm installed there; on a host that never had one, that step has nothing to do
([New terminals](/docs/using/new-terminals/#farhelm-no-longer-needs-tmux) has more). After you choose **Set up**, the
dialog closes and setup runs: the host's mark on the [navigation rail](/docs/using/manage-hosts/) shows a ring until it
is done. Setup progress also appears above your sessions, naming the current step; hover over that row to see every
step, or select it to open the host's row in the host list, which **Hosts** at the foot of the navigation rail opens.

<Screenshot
  name="add-a-remote-host/connected-host"

/>

The host now appears on the navigation rail, where choosing it shows only its sessions, and in the session launcher's
host menu; see [Start a
session](/docs/using/start-a-session/#choose-where-it-runs). On a Linux host, Farhelm runs as a service of your user
account, so it and its sessions keep running after you disconnect. It starts again when the machine boots where the
system allows that, and at your next login where it does not.

On a remote Mac, setup places Farhelm's program in `~/.local/lib/farhelm` and its data in `~/.local/state/farhelm`.
It creates a background job, `io.farhelm.supervisor`, with its file in `~/Library/LaunchAgents`. The setup question
names those paths and the job before you confirm. The job runs Farhelm right away, keeps it running after you
disconnect, and starts it again after a crash. After a reboot, choose **Update** from the host's `⋯` menu to start it
again ([Manage hosts](/docs/using/manage-hosts/#update-a-host) covers that action). Automatic startup at screen login
has not been verified. This does not change how the desktop app runs Farhelm on your own Mac.

To have Farhelm ask again before setting up a host, turn off **Set up new hosts without asking** under **Hosts** in the
settings behind the gear at the foot of the navigation rail; [Manage hosts](/docs/using/manage-hosts/) has the rest of a host's settings.

## If something goes wrong

- When a host asks you to sign in, when Farhelm opens or after a connection drops, an amber key on its mark on the
  navigation rail and a row above your sessions tell you. Choose **Answer** to see the question. If it expired, you
  cancelled it, or signing in failed, choose **Sign in** to try again. **Update**, **Uninstall** and **Re-run** can ask
  the same way before they start ([Sign in to a host](/docs/using/manage-hosts/#sign-in-to-a-host)). To silence the
  chime, turn off **SSH sign-in** under **Settings → Notifications**.
- When a regular SSH connection fails, check that `ssh <destination> true` works in a terminal. For a Tailscale host,
  check that Tailscale is running and the destination is a node name or IP on your Tailscale network.
- A Linux host without systemd's services for your user account cannot be set up automatically, and the dialog says so.
- A Mac with the Farhelm desktop app installed cannot be set up, updated or uninstalled over SSH. If Farhelm is already
  running there, adding the host still uses it as it is. If a Mac lacks a command needed for setup, the dialog names the
  missing command.
- When setup fails partway, the host appears above your sessions with **Details**, and its mark on the navigation rail
  shows a warning. Choose **Details** to open the host list at that host and see which step failed. **Re-run** in its
  `⋯` menu tries again.
- Adding a destination that is already in your host list is refused, and the dialog names that host. To set it up
  again, use **Update** in its `⋯` menu, or **Re-run** if its setup failed.

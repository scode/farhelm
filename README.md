## Why should I use it?

- **The agent's own TUI.** You drive the real Claude Code, Codex, or whatever you run, keystroke for keystroke, not a
  wrapper around it.
- **Screenshots and files.** Paste or drop one into the terminal and the agent has it, even when the agent runs on a
  machine across the network.
- **Downloads.** When the agent mentions a file it made, hover over the path and click to download it.
- **Nothing loses its place.** Close the laptop, restart Farhelm, reboot the remote host: every session is still in the
  list, and restarting it picks the agent's conversation back up.
- **Templates.** Often start Codex in YOLO mode on a checkout of `acme/web` on `build-box`? Save that as a launch
  template, then in the Mac app press Cmd+N, type `tl:web`, and press Enter twice: once to apply it, once to launch.
- **Change one thing.** Want this session again, but with Codex instead of Claude? **clone** opens the launcher with
  everything already filled in, so you change just the agent and launch. **replace with** does the same, and swaps the
  new session in for this one.
- **Agents start sessions.** Tell your agent
  `$farhelm for each of the TODO items above, start a session in a new managed checkout of acme/web, named after the item`,
  and it will. Farhelm asks you before each one starts, unless you have told it to trust that host.
- **Version control.** Farhelm works in any directory, whatever it uses for version control. It can also manage
  checkouts of your GitHub repositories: a fresh clone for each session, moved to the trash when you are done with it.

## How it works

  <picture>

      alt="How Farhelm works: the helm on your laptop lists every session from every host and reaches a supervisor on each remote box over ssh; the selected session's real terminal fills the pane"

  </picture>
</p>

Farhelm has two parts. The **helm** is what you look at, usually the Farhelm app on your Mac: it keeps your list of
hosts and shows every session. A **supervisor** runs on each machine, your Mac included, and keeps that machine's agents
and their terminals running. The helm reaches each supervisor over SSH. Nothing listens on a network port, nothing goes
through a relay, and every box in the diagram can restart without losing a session.

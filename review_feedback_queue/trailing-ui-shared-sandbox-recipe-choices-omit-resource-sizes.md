# Shared sandbox recipe picker omits CPU and memory sizes

Reviewed commit: 00de0b6c9cf206f1a7c9c5ad1c76b5b10eaf85db

## TLDR

Source-confirmed review record: users choosing a new Tensorlake sandbox cannot compare recipes' CPU and memory allocations in the launcher recipe list; it only shows names and refusal reasons. Synthesis confirms the omission is the native select's actual option text: environment_ui.rs:562-608 uses select plus options whose only label is display_peer(recipe.name) with refusal text at :598-601. No recipe.size is included. list/create_form.rs:7440-7450 installs this shared picker in the actual launcher, with no size disclosure in its host_notes :5665-5691 or sandbox help :8400-8418. Exact product contract, SPEC.md:1440-1442: "The launcher's **New sandbox** segment lists recipes with a cube mark and CPU and memory size. A recipe without a built snapshot is disabled with **No snapshot yet**." The size obligation applies to the choices before launch; using native options does not preclude adding CPU/memory as plain option text. No claim is made that a native option must support embedded SVG, and the finding does not require replacing the native control. Retained consent is separate: create_form.rs:9219-9246 renders the creation question, with CPU/memory/disk at :9227, billing consequences, pricing link and Create and launch answer. That later disclosure limits impact but does not supply missing chooser comparison. SPEC.md Sandbox sessions separately permits skipping that question only under the acknowledged Create Tensorlake sandboxes without asking choice; that authorized opt-out does not turn this chooser omission into a billing-authority bypass.

# Delete documentation overstates the admission timeout's decision guarantee

Reviewed commit: 00de0b6c9cf206f1a7c9c5ad1c76b5b10eaf85db

## TLDR

Unverified collection: the new Delete documentation gives maintainers a stronger deadline and no-decision guarantee than this handler implements. A future caller or test relying on it could mistake an expired reply deadline for proof that deletion cannot still occur. The established issue is internal contract documentation, not an observed late deletion or a proved false message in the shipped UI. Exact source: handlers.rs:1424-1427 says 'the waits before the decision are bounded (`SupervisorTimeouts:: seal_delete_wait`): a helm with its own deadline is waiting, and a decision taken after it gave up would contradict the "nothing was decided" it showed the user.' The inline claim at 1454-1458 begins 'Every lock this Delete waits for before deciding is inside the bound'. Actual timeout at 1459-1471 contains the agent fence, general permit, directory admission and lifecycle claim only.

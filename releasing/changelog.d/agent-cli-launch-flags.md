kind: breaking

Agents can now start sessions the way you do in the session launcher. `farhelm agent create` and `farhelm spawn` take `--agent` with `--model`, `--effort`, `--permissions` and `--trust` for an agent launch, and `--command` with `--yolo` or `--no-yolo` (plus `--agent` and `--resume-command`) for a command launch. `--template <name>` applies one of your launch templates, and can be repeated: templates apply first, in order, and the other flags then change the result, so `--template my-codex --model gpt-6-luna` is `my-codex` with a different model. A template can supply the folder, host and title too, so those flags can then be left out. The CLI never fills a gap from what you last chose in the launcher: a choice no template or flag sets is the agent's own default, and a launch missing something it needs is refused naming the flag. `farhelm agent templates` lists your templates and what each sets, showing a command line or resume command only as set, without its text; agents can apply templates but not create or change them. Retrying a create with the same idempotency key and the same flags returns the session the first attempt started, even if a template it names was edited in between (for up to 30 days).

`farhelm spawn` no longer requires `--inherit-agent`: it takes either `--inherit-agent`, which still runs the session's own launch with no helm involved, or the launch flags, which need the session to be open in Farhelm, because the helm resolves them. It still creates only on its own host, so a template that sets a host is refused there, and a template that sets a fresh GitHub checkout is refused on the command line. Giving `--yolo` with `--no-yolo`, or any launch flag other than `--template` twice, is refused, as is `--inherit-agent` with any launch flag. `--no-resume-command` drops a resume command a template set. The `--json` schema version of the `farhelm agent` listings is now 6.
